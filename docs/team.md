Наставник обоих новичков — лид. Задачи новичков подобраны так, чтобы каждая давала **понимание**, как устроен проект, и **результат, который виден** на защите. Никто не делает «чёрную работу» вслепую.

У участников 2 и 3 есть готовые промты для их ИИ-помощника: он объясняет, ведёт по шагам и пишет отчёт о проделанном. Промты — в [`docs/prompts/`](prompts).

## Как мы работаем вместе

- **Git.** Каждый работает в своей ветке: `hw/<задача>` у «Железа», `sw/<задача>` у «Софта». Готово → Pull Request → лид проверяет и вливает. Новичкам проще всего через [GitHub Desktop](https://desktop.github.com).
- **Ядро не трогаем без лида.** `swarm_core.h` и `flywheel.h` меняет только лид или с его ревью: от них зависят все тесты.
- **Отчёт раз в неделю.** 5–10 строк в Issue «Неделя N»: что сделано, что не вышло, вопрос к лиду. Формат отчёта ИИ-помощника подходит как есть.
- **Созвон раз в неделю, 30 минут.** Каждый показывает результат вживую (экран, видео, симуляция), а не рассказывает.
- **Правило 20 минут.** Застрял — 20 минут ищешь сам (с ИИ), потом сразу пишешь лиду.
- **Готово** = работает у другого человека + описано в README или docs + есть видео или скриншот.

## 2. «Железо» — схема, датчики, 3D

Цель для участника: понять, **как из деталей и проводов получается робот**, как датчик превращается в число, а число — в решение автомата. После этих задач можно самостоятельно собрать и отладить схему на ESP32 и спроектировать деталь.

| # | Задача | Чему научит | Готово, когда |
|---|---|---|---|
| Ж1 | Основы Wokwi: мигающий светодиод, кнопка, RGB-светодиод через ШИМ, сервопривод | `setup()`/`loop()`, `digitalWrite`, `analogWrite`, `millis()` вместо `delay()` | 4 своих проекта Wokwi, ссылки в Issue |
| Ж2 | Собрать схему модуля **с нуля** по таблице из [hardware.md](hardware.md), не копируя `diagram.json`; потом сравнить с готовой | читать распиновку, подключать датчики, искать ошибки в проводах | своя схема работает с прошивкой модуля |
| Ж3 | Запустить модуль в Serial-режиме (`USE_MQTT 0`) и **руками провести его по всем 8 состояниям**: вставлять JSON соседа в монитор, жать кнопки, крутить потенциометр | как работает конечный автомат и протокол изнутри | таблица «действие → состояние → цвет» совпадает с [demo.md](demo.md); видео |
| Ж4 | OpenSCAD: открыть `module_body.scad`, поменять размер ребра и магнитов, отрендерить, экспортировать STL | параметрическое проектирование | 2 скриншота «было/стало», STL в ветке |
| Ж5 | Добавить в Wokwi акселерометр MPU-6050, считать g и наклон, вывести на OLED g и обороты маховика из `rpmForPivot()` | датчик → число → физика → решение | на OLED видно g ≈ 9,8 и ≈ 8 900 об/мин; при смене g в Wokwi обороты меняются |
| Ж6 | Напечатать маховик и крюк (если есть принтер), **взвесить** маховик, вписать массу в `FlywheelSpec`, прогнать тест и посмотреть, как изменились обороты | проверка расчёта реальностью | фото на весах, PR с новой массой, объяснение изменения |
| Ж7 | Список деталей со ссылками и ценами на два модуля + стоимость двух плат для лида | бюджет и реальные компоненты | таблица в `hardware.md` |
| Ж8 | На защите: показать схему и 3D-модель, объяснить расчёт переката на пальцах | говорить о своей работе | 2 минуты рассказа без бумажки |

Промт для ИИ-помощника: [`prompts/zhelezo.md`](prompts/zhelezo.md).

## 3. «Софт и защита» — тесты, веб, данные

Цель для участника: понять, **как проверяют программы и как превращают данные в убедительную историю**. После этих задач можно писать тесты на C++, менять веб-страницы на JavaScript и строить живые панели данных.

| # | Задача | Чему научит | Готово, когда |
|---|---|---|---|
| С1 | Запустить тесты (`make`, `make trace`), прочитать `test_core.cpp`, объяснить своими словами 3 любых теста | что такое автотест, «виртуальный эфир», как читать журнал | короткий текст в Issue, разобран журнал `make trace` |
| С2 | Написать **свой** тест: например, авария во время стыковки или два разведчика одновременно | писать тесты на C++, думать о крайних случаях | тест в PR, проходит, лид одобрил |
| С3 | Веб-демо, стенд «Рой»: счётчики для жюри — время сборки фигуры, число стыковок, сбоев и зарядок | JavaScript, состояние программы, метрики | цифры видны на странице; скриншот |
| С4 | Веб-демо, стенд «Два модуля»: перенести из прошивки бурю и зарядку (`STORM`, `LOW_POWER`, `CHARGING`) в JS-копию автомата, добавить кнопки | конечный автомат изнутри, перенос логики между языками | на стенде работают буря и зарядка, журнал показывает `STORM` |
| С5 | Панель телеметрии: страница подключается к тому же MQTT-брокеру (через WebSocket) и показывает **живые** модули из Wokwi: состояние, заряд, соседа | MQTT, асинхронный JavaScript, визуализация данных | две симуляции Wokwi видны на панели в реальном времени |
| С6 | Видео 3 минуты, презентация, список из 15 вероятных вопросов жюри с ответами | рассказывать о технике понятно | видео, слайды, документ с вопросами |

Промт для ИИ-помощника: [`prompts/soft.md`](prompts/soft.md).

5. MQTT: библиотека PubSubClient (прошивка) и [MQTT.js](https://github.com/mqttjs/MQTT.js) (панель телеметрии, для «Софта»).
