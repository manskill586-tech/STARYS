# Как устроен мозг модуля

← [на главную](../README.md)

## Два слоя кода

```
firmware/src/
├── swarm_core.h   МОЗГ  — автомат и протокол. Чистый C++, без Arduino.
└── main.cpp       ТЕЛО  — датчики, MQTT, светодиод, сервопривод, OLED.
```

`main.cpp` в каждом проходе `loop()` делает одно и то же:

1. читает датчики и собирает их в структуру `Inputs`;
2. вызывает `module.tick(inputs)`;
3. забирает исходящие сообщения `module.popOutgoing()` и публикует их в MQTT и Serial;
4. принятые из MQTT или Serial сообщения передаёт в `module.onMessage()`;
5. выводит на светодиод `module.led()` и ставит сервопривод по `module.latchClosed()`.

Мозг ничего не знает про пины, Wi-Fi и JSON. Поэтому его можно проверить тестами на компьютере ([`firmware/test`](../firmware/test)) и без изменений перенести на другое железо или другой транспорт (ESP-NOW, ИК).

## Состояния

| Состояние | При входе | Пока в состоянии | Выход |
|---|---|---|---|
| `BOOT` | — | ждёт `sensorsOk && netReady` | → `SEARCH` |
| `SEARCH` | сбросить соседа, сразу послать `HELLO` | `HELLO` раз в 1 с; если свой датчик < 20 см и есть свежий сосед с `near:true` — послать `DOCK_REQ` | → `DOCKING`; на чужой `DOCK_REQ` при `near` — `DOCK_ACK` и → `DOCKING` |
| `DOCKING` | `agreed = false` | ждёт `DOCK_ACK`, потом касание | касание или `DATA` соседа → `LINKED`; нет ответа 5 с или касания 15 с → `SEARCH` |
| `LINKED` | закрыть защёлку | `DATA` раз в 1 с | тишина 4 с или `BYE` соседа → `SEARCH` |
| `FAULT` | открыть защёлку, послать `BYE` | пауза | через 3 с → `SEARCH` |

Из любого рабочего состояния (`SEARCH`, `DOCKING`, `LINKED`) нажатие кнопки «Авария» переводит модуль в `FAULT`. Срабатывает **фронт** нажатия, поэтому зажатая кнопка не держит модуль в аварии вечно.

## Тайминги

Все значения — в структуре `starys::Config`, их можно менять без правки логики.

| Параметр | Значение | Зачем |
|---|---|---|
| `helloPeriodMs` | 1000 мс | как часто «кричать» в поиске |
| `peerTtlMs` | 3000 мс | сколько помнить услышанного соседа |
| `dockDistanceCm` | 20 см | ближе — можно стыковаться |
| `dockTimeoutMs` | 5000 мс | ожидание `DOCK_ACK` |
| `contactTimeoutMs` | 15000 мс | ожидание касания после согласия |
| `dataPeriodMs` | 1000 мс | частота `DATA` в связи |
| `linkTimeoutMs` | 4000 мс | молчание соседа = разрыв |
| `faultPauseMs` | 3000 мс | пауза после аварии |

## Почему без `delay()`

`delay(1000)` замораживает весь модуль на секунду: он не слышит соседа, не видит кнопку и не замечает разрыв. Вместо этого каждое ожидание — это сравнение `now - отметка >= период`. Один проход `loop()` занимает миллисекунды, и модуль реагирует на всё сразу.

## Защита от типичных ошибок

| Ситуация | Что делает код |
|---|---|
| Своё же сообщение вернулось из MQTT | игнорируется (`from == id`) |
| Сообщение адресовано другому модулю | игнорируется (`to != 0 && to != id`) |
| Оба модуля одновременно послали `DOCK_REQ` | встречный запрос считается согласием, оба отвечают `DOCK_ACK` |
| Датчик видит кого-то, но неясно кого | стыковка только с тем, кто сам прислал `HELLO` с `near:true` |
| Касание нажали только на одном модуле | первый `DATA` от согласившегося соседа переводит в `LINKED` и второго |
| Очередь исходящих переполнилась | выбрасывается самое старое сообщение |

## Тесты

[`firmware/test/test_core.cpp`](../firmware/test/test_core.cpp) соединяет несколько модулей виртуальным «эфиром» и прогоняет время шагами по 50 мс.

| Тест | Что проверяет |
|---|---|
| `testDemoScenario` | весь сценарий защиты: поиск → стыковка → связь → авария → снова связь |
| `testLinkLoss` | обрыв связи: оба модуля возвращаются в поиск и стыкуются снова |
| `testNoAck` | сосед не ответил на `DOCK_REQ` — тайм-аут |
| `testNoContact` | договорились, но касания нет — `BYE` и поиск |
| `testBootWaitsForNetwork` | без сети модуль не выходит из `BOOT` и светится белым |
| `testIgnoresForeignTraffic` | третий, дальний модуль не вмешивается в чужую стыковку |
| `testMessageNames` | имена сообщений переводятся туда и обратно |

```bash
cd firmware/test && make trace
```
